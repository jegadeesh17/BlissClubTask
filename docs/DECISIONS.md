# Architectural & Operational Decision Records (ADRs)

## ADR-001: GitHub Pages Client-Side Dashboard Architecture
- **Date:** 2026-10-27
- **Status:** APPROVED
- **Context:** The project requires an interactive decision tool for an interview. Traditional cloud server options (Streamlit Cloud, Heroku) suffer from cold starts and sleep timeouts, creating awkward lag in interviews.
- **Decision:** Build a fast, client-side web application hosted on GitHub Pages (`docs/index.html`) using Tailwind CSS and Chart.js, populated by a pre-computed JSON dataset generated by the Python engine (`python scripts/export_analytics.py`).
- **Consequences:** Blazing fast load times (<200ms), zero cloud hosting costs, 100% reliability during live interview presentations, and full interactive slider capabilities for volume simulation.

## ADR-002: COD Minimum Baseline Calculation
- **Date:** 2026-10-27
- **Status:** APPROVED
- **Context:** The rate card defines COD charges as flat fee (₹25–₹28) or COD Min % (1.2%–1.5%), but the dataset lacks an `Order Value` column.
- **Decision:** Use the flat COD fee per AWB as the baseline calculation for all COD orders, explicitly stating this assumption in the executive briefing and dashboard notes.
- **Consequences:** Consistent, mathematically verifiable baseline freight and COD expenditure without hallucinated order values.

## ADR-003: Phased Volume Reallocation Strategy
- **Date:** 2026-10-27
- **Status:** APPROVED
- **Context:** Aggregator A3 handles 73% of volume despite higher prices. A sudden 100% volume shift to A1/A2 would risk carrier capacity collapse and SLA degradation.
- **Decision:** Implement a phased reallocation strategy: pilot 20–30% volume shift in Zone A/B to A1/A2 while maintaining A3 as anchor partner, coupled with weekly delivery SLA gates.
- **Consequences:** Captures immediate cost savings (₹3–5 Lakhs/month) while preserving delivery performance and partner relationships.

## ADR-004: Three-Stage SLA Funnel Architecture
- **Date:** 2026-10-27
- **Status:** APPROVED
- **Context:** Need to establish operational accountability between internal warehouse teams and external logistics partners.
- **Decision:** Split the lifecycle into 3 measurable stages based on available timestamps:
  1. *Warehouse Fulfillment:* `Order Date` $\rightarrow$ `AWB Assignment Time` (SLA: $\le 12$h)
  2. *Handover & Dispatch:* `AWB Assignment Time` $\rightarrow$ `Pickup Date` (SLA: $\le 12$h)
  3. *In-Transit & Last-Mile:* `Pickup Date` $\rightarrow$ `Delivered Date` (SLA: Zone A/B: 24–48h; Zone C/D: 48–96h; Zone E: 120h)
- **Consequences:** Clear, distinct accountability preventing couriers and warehouse teams from blaming each other for overall lead time inflation.
